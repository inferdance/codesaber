# Pi(Mario Zechner/badlogic 的 pi-mono)深度架构分析报告

> 分析对象:`~/ccc/agent-research/pi`(下文 `file:line` 相对仓库根,版本 0.84.2)。除 `packages/` 十个包外,根目录还包含 `scripts/`、`AGENTS.md`、`tui-plan.md` 等。

## 1. 总体架构:分层清晰的 npm workspaces monorepo

根 `package.json:4-11` 声明 workspaces:`packages/*`。构建脚本 `package.json:16` 的手工顺序(tui → telemetry → ai → agent → sqlite backend → protocol → client → server → coding-agent)精确反映依赖分层:

| 包 | 职责 | 关键依赖 |
|---|---|---|
| `packages/telemetry` | 厂商中立的遥测契约/Schema | 无 |
| `packages/ai`(pi-ai) | 统一多 provider LLM API | telemetry |
| `packages/agent`(pi-agent-core) | Agent 运行时:loop、工具调用、状态、会话 harness | pi-ai |
| `packages/tui`(pi-tui) | 差分渲染终端 UI 库(零依赖 pi 生态,可独立使用) | 无 |
| `packages/coding-agent` | 交互式编码代理 CLI(`pi` 命令) | 以上全部 |
| `packages/protocol` / `client` / `server` | 面向远程会话的帧式 CBOR 二进制协议与实现 | agent |
| `packages/session-backends/sqlite-node` | 会话的 SQLite 后端 | agent |
| `packages/evals` | 评测 | — |

分层原则严格:pi-tui 不依赖任何 pi 包;pi-agent 只认 pi-ai 的抽象;coding-agent 才引入 Node 专有能力(fs/child_process)。供应链加固:依赖全钉版、`npm-shrinkwrap`、生命周期脚本白名单、`min-release-age=2` 防新投毒。

## 2. 统一 LLM API 层(pi-ai)

**双轴抽象:API(线协议)× Provider(厂商)**。`packages/ai/src/types.ts:17-27` 定义 10 种已知线协议(`anthropic-messages`、`openai-completions`、`openai-responses`、`google-generative-ai`、`bedrock-converse-stream`…),`types.ts:35-75` 列出约 40 家厂商。模型目录由脚本生成(`src/models.generated.ts`),保证价格/上下文窗口等元数据可机检。

**统一消息与事件模型**:`types.ts:419-465` 定义 `UserMessage/AssistantMessage/ToolResultMessage`,内容块为 `Text/Thinking/Image/ToolCall`;`Usage` 含 cacheRead/cacheWrite 与成本。工具即 `{name, description, parameters: TSchema}`(TypeBox)。流式事件 `AssistantMessageEvent` 标准化为 `start → text/thinking/toolcall_{start,delta,end} → done|error`。`StreamFunction` 契约(`types.ts:322-334`)规定**错误必须编码进流的 `stopReason`,不得抛异常**——上层重试逻辑对 provider 无感。

**跨 provider 规范化**:`src/api/transform-messages.ts:56-80` 做工具调用 ID 规范化(OpenAI 450+ 字符 ID → Anthropic 字符集)及非视觉模型的图片降级。`OpenAICompletionsCompat`(`types.ts:555-623`)提供 20+ 个兼容开关(thinkingFormat、maxTokensField、requiresThinkingAsText…)。

**OAuth 订阅登录**:`src/auth/oauth/` 内含 Anthropic(Claude Pro/Max)、OpenAI Codex、OpenRouter、xAI、GitHub Copilot、Kimi、Radius 等流程:内置 client_id、PKCE、本地 `127.0.0.1` 回调 HTTP 服务,scope 含订阅级权限;以 `lazyOAuth({ isSubscription: true })` 挂载。扩展还能通过 `registerProvider` 注册全新 provider。

## 3. Agent 循环(pi-agent)

核心是 `packages/agent/src/agent-loop.ts:155-275` 的 `runLoop`:**外层循环**处理"agent 本要停止时又到来的 follow-up 消息",**内层循环**处理工具调用与 steering 消息。

- **steering/followUp 双队列**:`Agent` 类维护两个 `PendingMessageQueue`;steering 消息在下一次助手响应前注入(`agent-loop.ts:181-190`),实现"边跑边插话"。
- **流式就位更新**:partial assistant message 直接写入 context 末尾并随事件替换(`agent-loop.ts:326-369`)。
- **工具调度**:`executeToolCalls` 默认并行(`Promise.all`),但任一工具声明 `executionMode: "sequential"` 即整批串行;批量终止条件是所有结果 `terminate===true`。执行前 TypeBox 参数校验 + `beforeToolCall` 钩子(可 block),执行后 `afterToolCall`(可改写结果)。
- **错误防御**:`stopReason==="length"`(被 max tokens 截断)时**拒绝执行所有工具调用**、统一回错让模型重发(`agent-loop.ts:207-214,390-415`);找不到工具、参数校验失败均转为 `isError` 的 ToolResult 而非崩溃。
- **事件流**:`AgentEvent` 共 11 种,`agentLoop()` 返回 `EventStream<AgentEvent, AgentMessage[]>`,终值是本轮新增消息数组。

## 4. coding-agent 核心:AgentSession 与会话树

`packages/coding-agent/src/core/agent-session.ts:1-14`:**AgentSession 是唯一核心抽象,被 interactive/print/json/rpc 四种运行模式共享**。

**会话持久化 = 可编辑的 JSONL 树**。文件位于 `~/.pi/agent/sessions/<编码路径>/<时间戳>_<uuidv7>.jsonl`。首行 header,之后每行一个 entry;`CURRENT_SESSION_VERSION = 3`,entry 通过 `id/parentId` 构成树。entry 类型含 `message`、`model_change`、`compaction`、`branch_summary`、`custom`(扩展私有状态,不进 LLM 上下文)、`label` 等。加载时自动迁移 v1→v2→v3。

**resume/branch/fork**:当前上下文 = 从 leaf 到根的路径;`/tree` 导航只是移动 `leafId`(**原地分支**),切分支时可自动生成 `branch_summary`;`forkFrom()` 把源会话全部 entry 复制到新文件,header 记录 `parentSession` 指针且可换 cwd——支持跨项目"带着记忆搬家"。

**模式切换**:pi **没有** ask/code/full-access 三档权限模式(README 明确"Pi 不内置权限系统")。等价能力:工具白/黑名单(`--tools/-t`、`--exclude-tools/-xt`)与只读工具集 `createReadOnlyToolDefinitions`(read/grep/find/ls);默认仅启用 read/bash/edit/write。

**自动重试与压缩恢复**:可重试错误与上下文溢出分流——溢出触发 compaction 后重试(`willRetry` 事件字段);普通可重试错误指数退避 `baseDelayMs * 2^(n-1)`,重试前把错误消息从 agent 状态中移出但保留在会话文件里(`agent-session.ts:2779-2829`)。

## 5. 工具系统

内置 7 个工具:`read`、`bash`、`edit`、`write` + `grep`、`find`、`ls`(`core/tools/index.ts:83-84`)。

1. **TypeBox schema 定义**:`tools/bash.ts:41-44`,经 `ToolDefinition` 包装获得 `renderCall/renderResult` 自定义渲染、`executionMode`、`prepareArguments` 垫片、`toolSnippet`/`guidelines`(注入系统提示词)等能力。
2. **Operations 接口虚拟化**:每个工具的副作用抽象成可替换接口——`BashOperations` 允许把命令执行转发到 SSH/远程机;`BashSpawnHook` 可在 spawn 前改写 command/cwd/env。gondolin 微 VM 扩展正基于此实现"工具在沙箱内执行、认证在宿主机"。
3. **执行细节**:bash 输出流式回调(100ms 节流),超时/中止杀整棵进程树(`bash.ts:114-152`),超长输出截断并把全量落盘为 `fullOutputPath`;文件写操作经 `file-mutation-queue.ts` 串行化防竞态;edit 工具做 LF 规范化(`tools/edit.ts:366-367`)。

## 6. 扩展机制:"self-extensible" 的实现

扩展是普通 TypeScript 模块,由 **jiti** 加载;`VIRTUAL_MODULES` 把 pi 全家桶包预先静态打进二进制,再以虚拟模块形式供给扩展 import——解决 Bun 编译单文件后扩展无法 resolve 依赖的问题。自动发现路径:`~/.pi/agent/extensions/`(全局)与 `.pi/extensions/`(项目,需过信任门),支持 `/reload` 热重载。

`ExtensionAPI` 提供约 40 个生命周期事件订阅(覆盖 project_trust、session 全链路、context、provider 请求、agent/turn/message/tool 全链路、input、user_bash)、`registerTool/registerCommand/registerShortcut/registerFlag`、自定义渲染、会话动作、模型与 provider 控制(`setModel/registerProvider`)。

**配套资源体系**:**Skills** 遵循 Agent Skills 规范的 `SKILL.md` + frontmatter,在系统提示词中以 `<available_skills>` XML 清单出现,模型用 read 工具按 `<location>` 自取。**Commands** = 扩展命令 + prompt 模板 + skills。**Rules** 即上下文文件:沿目录祖先链收集 `AGENTS.md/CLAUDE.md`。**自我扩展**的闭环在系统提示词里:模型被告知 pi 的 docs/examples 路径并鼓励为用户写扩展。

## 7. 上下文管理

- **不注入文件树**(全库检索无 fileTree/repo map):pi 的哲学是让模型用 grep/find/ls 按需探索,系统提示词只给 cwd 一行。
- **Compaction**:触发条件 `contextTokens > contextWindow - reserveTokens`,三种 reason:manual/threshold/overflow;总结由独立 LLM 调用完成;压缩 entry 记录 `firstKeptEntryId` 与文件操作累积(`CompactionDetails{readFiles, modifiedFiles}`),使跨多次压缩后模型仍知道碰过哪些文件;扩展可用 `session_before_compact` 完全接管。
- **token 计量**:优先用 provider 真实 usage,无则按字符估算。

## 8. 提示词设计

`core/system-prompt.ts:28-162` 的 `buildSystemPrompt` 是纯函数:角色句 + **由当前启用工具动态生成的** Available tools 列表与条件化 Guidelines、pi 文档导航段(模型可自读文档)、`<project_context>` 包裹的 AGENTS.md/CLAUDE.md、skills 清单、cwd。支持 `customPrompt` 整体替换与 `appendSystemPrompt` 追加。

## 9. pi-tui:差分渲染与组件模型

组件契约极简:`render(width): string[]` + 可选 `handleInput` + `invalidate`,纯字符串行数组使组件可组合、可测试。调度上 `requestRender` 合帧、最小渲染间隔 16ms,而**键盘输入走立即渲染旁路**。真正的差分在新旧行数组逐行比较,只对变化区间发射光标移动/重绘,追加场景走 fast-path。其他亮点:APC 零宽 `CURSOR_MARKER` 序列支持 IME;锚点式 overlay;Kitty 图片协议;editor 组件带 kill-ring/undo-stack。

## 10. RPC / headless 模式

**JSON-lines over stdio**:stdin 收 JSON 命令、stdout 出 response/event;命令覆盖 prompt/steer/follow_up/abort、model/thinking 切换、compact、retry、bash、session 系列 fork/clone/get_tree/get_entries、export_html 等。`core/output-guard.ts` 接管原始 stdout 防污染协议流。妙在**扩展 UI 桥接**:headless 下 `ctx.ui.confirm/select` 被实现为 `extension_ui_request` 出站请求 + 挂起 Promise 表,宿主程序应答后恢复——同一扩展代码在 TUI 与 RPC 下都能弹窗。

**二进制远程协议**:`packages/protocol` 实现 4 字节大端长度前缀帧 + CBOR 编码 + TypeBox 全量 Schema;`packages/server` 管理握手/连接/会话/快照(transport 目前有 Unix socket)——把 pi 变成"常驻服务、多前端接入"的基础。

## 11. 权限与安全

pi **刻意不内置权限系统**,官方隔离方案是 gondolin 微 VM / Docker / OpenShell 三种容器化模式。它提供的是**构建权限系统的挂点**:项目信任门(`project_trust` 事件 + trust-manager)、`tool_call`/`user_bash` 拦截事件(文档示例即 rm -rf 确认门)、`BashOperations`/spawnHook 改写或外移执行。bash 工具本身没有命令解析器/白名单——超时杀进程树、输出截断是仅有的防线。

## 12. 最值得借鉴的工程设计

1. **极简内核 + 事件全开的扩展体系**:权限、provider、UI、压缩策略全部可被扩展替换甚至整体接管;扩展能注册 CLI flag/快捷键/命令,等于把产品自身的进化机制交给用户和模型自己。
2. **会话即人类可读的 JSONL 树**:单一 append-only 文件 + `id/parentId` 实现原地分支/树导航/带总结的切枝,fork 跨项目只靠复制行 + parentSession 指针;版本迁移器保证旧文件永续可用。
3. **API × Provider 双轴 + 兼容矩阵**:10 种线协议适配器 + 每模型 compat 开关,一份生成式模型目录,"加一个 OpenAI 兼容新厂"几乎零代码;统一事件流契约(错误不抛异常)让上层逻辑对 provider 无感。
4. **工具的 Operations 虚拟化**:副作用全部接口化,同一 agent 内核可以在本地、SSH、微 VM 沙箱间切换执行后端而不动工具 schema——权限问题被转化为部署问题。
5. **一套核心、四种前端、两种线协议**:AgentSessionEvent 归一化后同时服务 TUI/print/JSON/RPC,扩展 UI 经 request/response 桥接打通 headless;再往上有帧式 CBOR 的远程 server。

**总评**:pi 用约 1.7 万行核心代码(agent-loop 805 行、AgentSession 3437 行)证明了 coding agent 的本质复杂度并不高——难的是把每一层抽象都设计成可独立演进、可被第三方接管的开线协议,并辅以严格的工程纪律把它做成可持续的自扩展生态。
